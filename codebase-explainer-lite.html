ThreatIQ — 30-Second Hackathon Pitch

The Problem: SOC (Security Operations Center) analysts face thousands of disconnected alerts every single day ("Alert Fatigue"), leading to missed ransomware and zero-day breaches.
The Solution: ThreatIQ correlates raw security telemetry using a 15-minute sliding window (Union-Find), detects statistical anomalies with IsolationForest, computes an objective 7-factor risk score (0–100), retrieves MITRE ATT&CK & CVE intelligence via ChromaDB RAG, and produces 4-tier structured reasoning using Gemini LLM with automatic deterministic offline fallbacks.
Who it is for: Cybersecurity SOC teams, Tier-1/2 security analysts, and enterprise incident response units.

Reduction: 36.5% Noise Cut (50 events → 2 critical incidents)
Scoring: 7-Factor Formula (0 to 100 deterministic)
AI Reasoning: 4-Tier Strict (Evidence, Intel, Hypothesis, Action)
Offline Ready: 100% Zero-Cloud Fallback

Core Features (What makes it special)

1. Fast ML Anomaly Detection

Scikit-Learn IsolationForest normalizes outlier deviations into a 0.0–1.0 anomaly score without requiring pre-labeled training sets.

2. 15-Minute Sliding Window Correlation

Union-Find disjoint-set algorithm clusters related IP telemetry into coherent, multi-stage attack campaigns.

3. 7-Factor Mathematical Risk Engine

Calculates an objective 0–100 score across Base Severity, Anomaly, Asset Criticality, Exploitability, Evidence, Recency, and Threat Intel.

4. ChromaDB RAG Threat Intelligence

Embeds and retrieves matching MITRE ATT&CK techniques (T1078, T1548) and CVEs using Google Gemini embeddings.

5. 4-Tier Multi-Provider LLM & Offline Fallback

Structured AI synthesis with instant rule-based fallback if the API key is missing or offline.

6. 1-Click SOC Mitigation Actions

Analysts can immediately isolate hosts, block attacker IPs, or resolve incidents directly with SQLite audit logs.

Current Limitations
  • SQLite database restricts heavy write-concurrency under millions of parallel logs.
  • ChromaDB runs in-process on local disk; requires local storage persistence.
  • Rule-based offline fallback is functional but lacks the nuanced phrasing of Gemini.
Next Steps / Production Roadmap
  • Decouple ingestion with Apache Kafka / RabbitMQ message queue.
  • Migrate SQLite to distributed PostgreSQL / TimescaleDB with connection pooling.
  • Integrate active SIEM connectors (Splunk, Elastic, CrowdStrike APIs).

All Questions (18) Architecture ML & Scoring AI & RAG Security 🔥 Tough / Tricky (4)
Architecture & Value
What exact problem does ThreatIQ solve, and for whom?
Confident Answer: SOC (Security Operations Center) analysts hazaron repetitive alerts aur false alarms se overwhelmed hote hain ('Alert Fatigue'). ThreatIQ un raw security logs ko ingest karke ML anomaly detection, 15-minute sliding window correlation, 7-factor composite scoring, aur ChromaDB RAG reasoning se filter karta hai — 36.5% alert noise reduce karke sirf asli critical threats highlight karta hai.
Architecture & Value
How does your correlation engine work behind the scenes?
Confident Answer: Correlation engine (`backend/pipeline/correlation/engine.py`) ek 15-minute sliding window use karta hai. Same source IP ya common target asset ke related events ko Union-Find (Disjoint Set) algorithm ke zariye aapas mein group karta hai. Is tarah 50 scattered alerts 2 meaningful incident clusters mein tabdeel ho jate hain.
Detection & Scoring
Why did you use a 7-factor scoring formula instead of letting an LLM pick the score?
Confident Answer: LLMs numeric scoring mein inconsistent aur hallucinate karte hain. Hamne 7 strictly defined mathematical factors banaye: Base Severity (20), Anomaly (20), Asset Criticality (20), Exploitability (15), Evidence Density (10), Recency (10), aur Threat Intel (5). Yeh 0–100 score 100% deterministic, explainable, aur instant hota hai.
AI, RAG & LLM
How exactly is RAG implemented here, and what is stored in the vector database?
Confident Answer: ChromaDB vector store (`backend/rag/`) mein 2 curated collections hain: `mitre_attack` (12 techniques) aur `cve_summaries` (11 CVEs). Jab incident cluster banta hai, to uske event keywords aur tactics ko Google Gemini embeddings (`models/gemini-embedding-001`) ke zariye cosine similarity search se match karke relevant context nikala jata hai.
AI, RAG & LLM
What is the 4-tier LLM reasoning output structure?
Confident Answer: Gemini model (`gemini-3.6-flash`) se unstructured summary lene ke bajaye strict 4 tiers generate karwaye jate hain: (1) Observed Evidence (raw facts), (2) Retrieved Context (matching MITRE/CVE intel), (3) AI Interpretation (hypothesized attack path), aur (4) Recommended Action (concrete remediation playbook).
AI, RAG & LLM
What happens if the LLM provider fails, API key is missing, or the internet drops?
Confident Answer: Pipeline fail nahi hoti! Hamne `backend/llm/reasoning.py` mein deterministic rule-based fallback engine likha hai jo extracted events aur RAG matches ko parse karke instant 4-tier structured reasoning aur remediation steps offline generate kar deta hai.
Detection & Scoring
Why did you choose IsolationForest for anomaly detection?
Confident Answer: Security telemetry unlabeled hoti hai (pehle se labeled attack dataset available nahi hota). Scikit-Learn ka IsolationForest unsupervised tree partitioning use karta hai jo abnormal spikes aur zero-day behavior ko rapidly isolate karta hai. Iske outputs ko 0.0–1.0 score mein normalize kiya jata hai.
Frontend & UX
Why Next.js 14 and SWR on frontend instead of plain React with useEffect?
Confident Answer: SWR (`frontend/lib/hooks.ts`) automatic stale-while-revalidate client caching aur 5000ms background polling provide karta hai. Jab analyst incident explore karta hai ya decision action leta hai to instant UI update hoti hai without any layout flicker ya loading spinner delay.
Tech Stack
Why FastAPI for backend instead of Flask or Django?
Confident Answer: FastAPI modern Python 3.11 asynchronous ASGI framework hai jo high-throughput telemetry ingestion ke liye optimized hai. Saath hi Pydantic models automatically request validation aur OpenAPI Swagger documentation guarantee karte hain.
Security & Privacy
How does ThreatIQ handle customer data privacy when using cloud LLMs?
Confident Answer: Raw sensitive payloads ko backend par preprocess aur sanitize kiya jata hai; sirf anonymized attack telemetry aur abstracted tactics LLM prompt mein jati hain. Mazeed yeh ke platform local Ollama provider ko bhi support karta hai jo 100% on-premises offline chal sakta hai.
Performance
What is the end-to-end latency of the analysis pipeline?
Confident Answer: ML anomaly detection, correlation, aur 7-factor scoring sub-second (under 150ms) mein complete ho jate hain. Gemini LLM reasoning ke sath total time 1.5–2.5s hota hai, aur in-memory LLM cache match hone par < 50ms mein return karta hai.
SOC Workflow
Can an analyst take immediate remediation action from the interface?
Confident Answer: Bilkul. Incident detail modal par dedicated Action Panel hai jahan se analyst 1-click decision le sakta hai: Acknowledge, Isolate Host, Block IP, ya Resolve. Har action SQLite ke `analyst_actions` audit log mein save hoti hai aur status instantly sync hota hai.
Demo Scenario
What is 'Operation Shadow DB' that you showcase in the demo?
Confident Answer: Yeh realistic multi-stage cyber attack scenario hai jo `prod-db-01` par simulate hota hai: SSH brute-force login (T1078) -> Privilege escalation via sudo (T1548) -> Database dumping (CVE-2023-38606) -> Encrypted exfiltration. ThreatIQ ise correlate karke 91/100 critical incident declare karta hai.
Scalability
How would you scale this architecture to millions of logs per day?
Confident Answer: Current modular architecture production-ready abstractions par bani hai: (1) Ingestion endpoint ke samne Apache Kafka ya RabbitMQ message queue lagayein, (2) Celery/Redis distributed workers par pipeline parallelize karein, aur (3) SQLite ko PostgreSQL/TimescaleDB se swap karein.
Tough Question TRICKY QUESTION
Tricky: Why did you use SQLite instead of PostgreSQL or MongoDB?
Confident Answer: Honest answer: Hackathon context mein zero-configuration portability aur rapid local judge evaluation zaroori thi taake koi database server setup na karna pare. However, database layer (`backend/database/connection.py`) fully decoupled hai aur production mein easily PostgreSQL se swap ho sakti hai.
Tough Question TRICKY QUESTION
Tricky: What if the LLM hallucinates an attack that never happened?
Confident Answer: Hamne 3 strict guardrails lagaye hain: (1) Temperature 0.2 par freeze hai, (2) System prompt model ko strictly Tier 1 Evidence aur Tier 2 RAG context tak limit karta hai, aur (3) Har LLM explanation ke saath raw event logs aur mathematical score breakdown side-by-side verification ke liye available hoti hain.
Tough Question TRICKY QUESTION
Tricky: Isn't 36.5% alert reduction lower than tools claiming 90%?
Confident Answer: Honest answer: Commercial tools jo 90% claim karti hain aksar high-volume repetitive firewall pings drop karti hain jisse critical alerts miss ho sakte hain. Hamara 36.5% reduction ek highly curated 50-event targeted attack dataset par hai jahan zero false negatives ensure kiye gaye hain.
Tough Question TRICKY QUESTION
Tricky: Why is ChromaDB stored on local disk instead of Pinecone cloud?
Confident Answer: Local ChromaDB use karne se network latency khatam hoti hai, offline demo bina internet ke 100% reliable chalta hai, aur third-party cloud vector billing ka kharcha zero ho jata hai.
